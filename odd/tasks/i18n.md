# i18n (English + Spanish)

## Objective
Add English and Spanish to the whole UI. Technical terms and product vocabulary stay in English in both languages (see Glossary).

## Why
The user wants to learn and use Jev Lab in Spanish without losing the technical vocabulary (`choice`, `score`, `noul`, `confidence`...), so concepts map 1:1 to the docs and the API.

## Decisions
- Model inputs stay in English and are never translated: question `instructions` and `criteria`, preset `state`, the playground `DEFAULT_DRAFT`, and anything the user types. Reason: Jev is documented as best in English (`learn.mjs`), the demo engine heuristics are English-only, and the lab must test what Jev really receives. Decided with the user on 2026-09-20 (recommended option accepted).
- Only display copy is translated: UI labels, aria-labels, page titles, long-form explanations, example `title`/`tagline`/`pattern`/`lesson`/preset `label`, `decide()` output, and error messages shown to the user.
- Code snippets (`logic`, generated curl/JS/Python) stay in English, comments included.
- Answer/option ids (`billing`, `set_temperature`, `L1`, hazard ids) are data, shown as-is.
- Server stays English-only. The client maps stable error codes to translated messages and falls back to the server message.
- Mechanism: zero dependencies, isomorphic `lib/i18n.mjs` (runs in browser and Node) with `lib/i18n/en.mjs` and `lib/i18n/es.mjs`. `t(key, params)` with `{name}` interpolation, fallback es -> en -> key. English is the source of truth.
- `decide(answers, { policy, t })` takes `t`, defaulting to the English translator, so existing English assertions keep passing.
- Language preference: `jev-lang` in localStorage, default from `navigator.languages`, fallback `en`. `<html lang>` is set before first paint from `theme-init.js`. Switching re-renders the shell and the current route without a reload.
- Spanish register: neutral/professional, no regional slang.

## Glossary (stays in English in Spanish UI)
Jev, System One, TypeSafe, `noul`, `choice`, `score`, `confidence`, `probabilities`, `legend`, `state`, `questions`, `instructions`, `criteria`, `policy`, `threshold`, `weights`, `composite`, `routing`, `act`/`confirm`/`escalate`, `live`/`sample`/`demo` mode ids, Playground, pattern names (Speculative fan-out, Composite scoring, ...), API/env names (`TYPESAFE_API_KEY`, `jev-latest`, `/v1/systemone`), token, latency, curl/JS/Python.

## Constraints
- Zero runtime dependencies, no build step, ESM, JSDoc types.
- CSP is `script-src 'self'`: any new file is same-origin. Browser imports `/lib/*.mjs` only.
- The `errorBanner`/validation flow must keep working when a key is missing (fallback chain).
